# Repo Doctor: نقشه‌راه MVP

این سند مسیر رسیدن از صفر به یک ابزار قابل استفاده و قابل انتشار را مشخص می‌کند.
هر مرحله معیار «تمام‌شده» دارد تا مشخص باشد چه زمانی می‌توان جلو رفت.

## هدف محصول

> یک دستور، یک عدد، یک لیست کار. کاربر باید در کمتر از ۳۰ ثانیه بفهمد ریپویش
> چرا آماده‌ی انتشار نیست و دقیقاً چه کاری باید بکند.

## اصول طراحی (غیرقابل مذاکره)

1. **بدون شبکه.** هیچ درخواست HTTP؛ هیچ توکن؛ هیچ تلمتری. داده‌های مشورتی به‌صورت snapshot همراه ابزار می‌آید.
2. **بدون وابستگی اجرایی.** `dependencies: {}` — ابزاری که زنجیره‌ی تأمین شما را بررسی می‌کند نباید خودش زنجیره داشته باشد.
3. **اصلاحات غیرمخرب.** `fix` فقط فایل جدید می‌سازد؛ هرگز محتوای کاربر را تغییر نمی‌دهد.
4. **خروجی ماشین‌خوان پایدار.** schema نسخه‌دار + شناسه‌های ثابت قواعد.
5. **معماری ماژولار.** افزودن یک قاعده یا یک اکوسیستم نباید فایل‌های دیگر را لمس کند.

## فاز ۵ — نسخه‌ی ۰.۲

| قابلیت | ارزش | یادداشت پیاده‌سازی |
| ------ | ---- | ------------------ |
| `--baseline <file>` | فقط findingهای جدید را نشان بده | مقایسه بر اساس `partialFingerprints` |
| گزارش HTML | اشتراک‌گذاری با تیم | قالب تک‌فایلی بدون CDN |
| پشتیبانی monorepo | اسکن هر workspace جداگانه | تشخیص `workspaces`/`pnpm-workspace.yaml` |
| `--changed` | فقط فایل‌های تغییر‌یافته در PR | `git diff --name-only` |
| قاعده‌های سفارشی | تیم‌ها سیاست خودشان را اضافه کنند | `rulesDir` در config + اعتبارسنجی |

## فاز ۶ — نسخه‌ی ۰.۳ (به‌صورت اختیاری آنلاین)

- `--online` برای دریافت مشورتی‌های تازه (OSV) — **پیش‌فرض خاموش** و با هشدار صریح در مورد خروج داده.
- `update-data` برای به‌روزرسانی snapshot به‌صورت دستی.
- هرگز به‌صورت پیش‌فرض هیچ نام پکیجی ارسال نمی‌شود.

## آنچه در MVP نیست (non-goals)

- تحلیل AST یا اجرای کد پروژه — امنیت اول.
- دسترسی به GitHub API یا ریپوی خصوصی.
- حسابرسی کامل CVE — این کار ابزارهای تخصصی است؛ ما snapshot کوچک و شفاف داریم.
- امتیاز «مقایسه‌ای» با پروژه‌های دیگر — گمراه‌کننده است.
- هوش مصنوعی در مسیر اسکن — پیش‌بینی‌ناپذیری و هزینه؛ در آینده فقط به‌عنوان دستیار اصلاح.
